This document is the release handoff view. It separates repository implementation status from external release evidence that must still be collected before tagging `v0.2.0`.

## 1. Architecture Summary

KeenAI is implemented as a TypeScript modular monolith with pnpm workspaces. The current codebase follows the design intent of `apps/*` as runnable surfaces and `packages/*` as bounded domain or platform modules.

```text
Client surfaces
  apps/dashboard      Next.js operator console
  apps/portal         public customer/product portal
  apps/docs           documentation site
  apps/widget         embeddable Preact messenger

Service layer
  apps/api            Hono API, auth, webhooks, KB ingest, workflow/runtime endpoints

Domain and platform packages
  packages/shared     shared schemas, types, message parts
  packages/storage    Drizzle schema, store/vector/FTS abstractions
  packages/auth       JWT, sessions, RBAC helpers
  packages/llm        provider registry and model routing
  packages/agent      Copilot/agent context assembly and tools
  packages/memory     four-layer memory primitives
  packages/memory-tree KG and memory tree extraction
  packages/kb         KB/RAG ingest, connectors, eval, telemetry, bench
  packages/workflow   workflow DSL/runtime primitives
  packages/channels-* channel abstractions, email, IM adapters
  packages/mcp        MCP/custom action exposure
  packages/ui         shared UI components
```

Design docs describe additional bounded contexts such as inbox, conversation, ticket, feedback, roadmap, changelog, help center, notify, and analytics. In the current repository, these are implemented mainly through `apps/api`, `apps/dashboard`, `apps/portal`, and `packages/storage` schema/routes rather than split into separate packages. That is acceptable for the v0.2 modular-monolith state, but it should be called out as a packaging difference from the ideal module map.

## 6. Must Complete Before `v0.2.0` Tag

These items are not fully satisfiable by local repository edits alone. They require remote CI, deployed services, production/prod-like data, published media, or release operations.

| Priority | Item | Required evidence |
|----------|------|-------------------|
| P0 | Production KB quality proof | Local `KB_EVAL_REPORT_JSON` is now generated by `pnpm kb:eval:report`; final tag still requires production/prod-like `KB_TELEMETRY_REPORT_JSON` with `evidenceStatus: "passed"`, non-zero query count, faithfulness/Recall@5/stale-answer thresholds satisfied |
| P0 | Deployed API performance proof | `pnpm kb:bench` result against deployed API with P95 within threshold |
| P0 | Remote CI evidence artifact | Successful remote CI run with downloadable `v0.2.0-release-evidence` artifact |
| P0 | Live source connector proof | GitHub/Notion OAuth app credential proof plus live source ingest/webhook evidence |
| P1 | Copilot adoption evidence | `copilot:adoption:report --fixture` is available in CI; final acceptance needs production/prod-like report with accept rate >= 30% |
| P1 | Docker lite startup timing | `docker:lite:startup-report` dry-run is available in CI; final acceptance needs actual Docker-enabled report with API health <30s and DB health delta <5s |
| P1 | Tutorial videos | Rendered MP4s or YouTube/Bilibili publish links for v0.2 tutorials |
| P1 | Real Ollama runtime proof | `ollama:offline:demo` proves the local provider path with a loopback compatible server; final acceptance still needs `ollama serve` + local model runtime evidence |
| P1 | Release images and Helm proof | GHCR `0.2.0` API/Dashboard images plus Helm install/lint/template artifact from remote run |
| P1 | External KPI proof | Adoption, external teams, Featurebase parity, startup timing, and live ops metrics |
| P1 | Final release packaging | Passing `pnpm release:verify-external`, final changelog confirmation, `v0.2.0` tag, GitHub prerelease |

## 7. Current Verification Commands

The following commands are the local release evidence baseline already represented in release docs and the gap audit:

```bash
CI=true corepack pnpm lint
CI=true corepack pnpm typecheck
CI=true corepack pnpm test
CI=true corepack pnpm kb:eval
CI=true corepack pnpm kb:bench:local
CI=true KB_API_BENCH_DURATION=1 corepack pnpm kb:bench:api:local
CI=true RELEASE_EVIDENCE_DIR=/private/tmp/keenai-release-evidence corepack pnpm release:evidence
corepack pnpm release:verify-external artifacts/release/v0.2.0-external-evidence.json
helm lint deploy/helm/keenai
helm template keenai deploy/helm/keenai
```

`release:verify-external` should only be expected to pass for the real tag once the external evidence manifest points to actual remote artifacts, published media, deployed-service bench results, GHCR image refs, and the final GitHub Release URL.
